Project Overview

I wrote roarm_cpp_lite as a lightweight C++ library for controlling the Waveshare RoArm M3 over serial. It provides a small interface to the arm's JSON command protocol, with an API inspired by the official Waveshare SDK.

The goal is straightforward: link the controller into an existing C++ application and communicate directly with the arm, without requiring a Python runtime or ROS. The library focuses on communication and joint control; Cartesian inverse kinematics is handled by a separate solver.

What I Built

  • Joint control: Send six-joint targets in degrees or radians, with speed and acceleration passed through to the firmware.
  • Serial interface: Configure the device path and baud rate, send raw JSON commands, and read feedback lines.
  • Command formatting: Convert joint vectors into the firmware's degree and radian command formats.
  • Feedback experiments: A background reader stores parsed values in a mutex-protected vector for access through pose_get().
  • Reusable build: A CMake target exports the headers and links the serial backend and thread dependencies for consuming applications.

Library Architecture

The roarm class owns the serial connection and command interface. Shared helpers handle JSON formatting and feedback conversion, while ThreadSafeVector protects cached feedback. Serial transport uses the Linux sources of wjwwood/serial, fetched at a pinned commit.

The build produces libroarm_cpp_lite.a and its serial backend as static libraries. The project uses C++17, CMake 3.18 or newer, and Linux, and is released under Apache-2.0.

Integrate into a C++ Project

A consuming application can use CMake's FetchContent to download and link the library. Pin GIT_TAG to a specific commit when a reproducible build is needed.

cmake_minimum_required(VERSION 3.18)
project(robot_app LANGUAGES CXX)

include(FetchContent)
FetchContent_Declare(roarm_cpp_lite
    GIT_REPOSITORY https://github.com/HootSoon/roarm_cpp_lite.git
    GIT_TAG main
)
FetchContent_MakeAvailable(roarm_cpp_lite)

add_executable(robot_app main.cpp)
target_link_libraries(robot_app PRIVATE roarm_cpp_lite)

Serial Feedback Example

Include roarm.hh, open the port, and request raw feedback. Construction opens the serial connection; it does not call the library's initialization motion.

#include "roarm.hh"
#include <chrono>
#include <iostream>
#include <thread>

int main() {
    roarm arm("/dev/ttyUSB0", 115200);
    std::this_thread::sleep_for(std::chrono::seconds(3));

    // Request feedback without sending a movement command.
    if (!arm.send_command("{\"T\":105}\n")) {
        return 1;
    }

    for (int i = 0; i < 100; ++i) {
        const auto response = arm.read_line();
        if (!response.empty()) {
            std::cout << response;
        }
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
}

Joint Command Interface

Both control methods take six joint values in the order shown below, followed by speed and acceleration.

IndexJoint
0Base yaw
1Shoulder
2Elbow
3Wrist bend
4Wrist roll
5Hand / gripper
 
// With a connected controller, these calls move the arm.
arm.joints_angle_ctrl({0, 0, 90, 0, 0, 180}, 10, 10);
arm.joints_radian_ctrl({0, 0, 1.5708, 0, 0, 3.1416}, 10, 10);

Current Development Status

The library currently implements serial transport and joint commands. A successful write confirms that command bytes were sent; it does not confirm arrival. Background feedback parsing remains experimental, and the declared joints_angle_get() and joints_radian_get() methods are not yet implemented.

The calling application supplies joint-limit checks, trajectory planning, and collision handling. This keeps the communication library separate from the arm geometry and motion logic.
