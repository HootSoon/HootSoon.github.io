Project Overview

A.R.K.O.V. stands for Autonomous Rover with Kinematics, Odometry, and Vision. It is our UAFS Autonomous Vehicle Challenge project for the 2026–2027 season, bringing robotic-arm control, wheel-encoder odometry, and camera perception into a new rover codebase.

I am leading the AVC team and developing the rover software around focused C++ modules, with Python tools for vision and algorithm experiments. ARKOV builds on the experience from our earlier competition vehicles while giving the new work its own organized structure.

Status: In development. The repository contains subsystem implementations, hardware test programs, and integration scaffolding. Full autonomous operation and competition results for this rover are still ahead.

My Software Development Work

My work spans the interfaces between perception, robot state, and motion: converting sensor data into a map, estimating where the rover is, and calculating how the arm should reach a target.

  • Manipulation: Wrote a C++ inverse kinematics solver for the RoArm M3 Pro, carrying the Cartesian targeting and tool-pitch approach from my Python library into ARKOV.
  • Mapping & localization: Developed a voxel occupancy grid, 3D ray traversal, and a Monte Carlo particle filter with motion prediction, scan weighting, and resampling.
  • Hardware interfaces: Built camera, LiDAR, serial-microcontroller, and Linux joystick utilities with separate programs for testing the interfaces.
  • Movement research: Added encoder-based odometry and PID control modules, alongside pathfinding experiments.
  • Code organization: Separated the new code by subsystem and used Doxygen-compatible comments to support generated documentation.

RoArm Manipulation & C++ Kinematics

The arm solver accepts an XYZ target and an end-effector pitch angle. It finds the base yaw, projects the target into a vertical plane, subtracts the final link's offset, and uses the law of cosines to solve the shoulder and elbow. Wrist bend then maintains the requested pitch.

The implementation supports angle calculation without a controller, optional feedback-based arrival checks, and sampled line interpolation. My standalone roarm_cpp_lite library provides the serial-control interface used by the solver. Integration into the rover's main build is ongoing.

LiDAR Mapping & Particle-Filter Localization

The LiDAR interface uses Unitree's unilidar_sdk2 to read point clouds over serial. The voxel grid accumulates occupancy values, increasing them at measured endpoints and reducing them along free-space rays using 3D Bresenham traversal.

The particle filter maintains candidate rover poses. Motion prediction adds uncertainty to each candidate; scan weighting compares transformed LiDAR samples with the voxel map; resampling keeps candidates according to their relative weights. The implementation includes sensor pitch and height offsets and log-weight normalization.

A separate Polyscope test program displays the evolving voxel map from live LiDAR data. It is a development visualization for inspecting point-cloud parsing and map updates. The SLAM manager is integration scaffolding; its encoder inputs are still placeholders and its update loop is not yet enabled in the rover entry point.

Odometry, Drive Control & Pathfinding

The odometry module converts changes in left and right encoder ticks into traveled distance and heading change using wheel circumference, encoder resolution, and wheelbase. PID controllers provide a separate building block for drive feedback.

Linux joystick tests read controller events and send motor commands over serial. Pathfinding work includes breadth-first search, Dijkstra's algorithm, and artificial-potential-field experiments. These components are being developed and evaluated before being combined into a complete navigation loop.

Vision & Hardware Testing

C++ OpenCV utilities capture and display camera frames. Python vision tools load a YOLO TensorRT engine and return detections with labels, confidence scores, bounding boxes, and centers. The RoArm M3 Pro also has a separate AGX test-bench directory for manipulation and camera experiments.

The rover entry point currently exercises serial communication with an STM32 microcontroller. Keeping hardware checks separate from the full autonomy loop lets me inspect individual interfaces as integration progresses.

Codebase & Development Direction

The new season's work is under ARKOV/ in the AVC repository, with modules for manipulation, localization, SLAM, odometry, PID, pathfinding, cameras, LiDAR, and voxel visualization. CMake configures the C++17 rover build and its OpenCV, serial, and Unitree LiDAR dependencies.

The next stage is to connect live encoder feedback, map updates, localization, navigation, and arm commands into a coordinated rover system, then validate that behavior on hardware. The earlier vehicles' achievements and engineering notebook remain documented on the 2024–2026 AVC project page.
